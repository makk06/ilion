# 기본 추천 상위 장소 상세 보강 (2026-09-12)

내부망의 임시 백엔드 테스트 페이지에서 서울·부산의 가까운 장소 대부분에 설명이 없었다. 전국 TourAPI 목록 45,716곳에는 이름·주소·좌표 등이 저장돼 있지만 설명은 별도 `detailCommon2` 조회로 채워진다. 이전 [시범군 개선 검증](./pilot-improvement-2026-09-12.md)은 세 도시에서 균형 있게 고른 360곳의 상세를 완료했으나, 기본 추천 상위 10곳과 반드시 일치하지는 않았다.

이번에는 테스트 페이지의 고정 위치 서울(37.5665, 126.9780), 부산(35.1796, 129.0756), 제주(33.4996, 126.5312)에서 반경 10km·기본 거리순 추천 상위 10곳씩을 다시 계산했다. 설명이 없는 20곳 모두 연결된 TourAPI 원본과 상세 조회용 콘텐츠 유형 ID가 있었다. 실제 사용자의 조회 빈도나 위치 정보는 수집하지 않았으므로, 이 세 고정 위치의 반복 노출을 우선순위 대용 지표로 사용했다.

| 기본 추천 상위 10곳의 설명 보유 | 수집 전 | 수집 후 |
| --- | ---: | ---: |
| 서울 | 1/10 | 10/10 |
| 부산 | 1/10 | 10/10 |
| 제주 | 8/10 | 10/10 |
| 합계 | 10/30 | 30/30 |

20곳에 대해 공통 상세만 조회하는 일회성 작업을 등록하고 워커를 실행했다. `detailCommon2`의 `overview`로 설명을 얻고, 이번 대상에 행사가 없으므로 추가 호출이 필요한 `detailIntro2`는 생략했다. 워커의 기본 2회 호출 동작은 유지하면서, 작업에 `include_intro=false`가 있으면 예산을 1회만 차감하고 공통 상세만 가져오도록 했다. 정기·보충 예산에서 각 10회를 사용했고 20개 작업 모두 성공했다. 20곳 모두 설명을 받았고 16곳은 상세 이미지 URL도 받았다. 전체 설명 보유 장소는 387/45,716(0.85%)에서 **407/45,716(0.89%)**로 늘었다. 당일 TourAPI 워커 예산 기록은 **911/1,000회에서 931/1,000회**로 증가했고, 대기·실패 작업은 0개다.

수집 직전 SQLite 백업은 `/private/tmp/feature-be-recommendation-core-before-top10-details-20260912.sqlite3`에 남겼으며 무결성 검사는 `ok`였다. 대상 목록과 수집 전 기준값은 `/private/tmp/feature-be-recommendation-core-top10-detail-targets-20260912.json`에 남겼다. 실제 내부망 페이지의 세 위치 모두 결과 10개와 설명 10개가 표시되고 빈 설명 문구는 없음을 HTTP GET/POST로 확인했다. 로컬 SQLite만 변경했으며 푸시·배포는 하지 않았다.

이 결과는 세 고정 위치의 현재 기본 추천을 읽기 좋게 만든 것이다. 다른 좌표·반경·선호 조건에서는 여전히 상세가 없는 장소가 나타날 수 있다. 추천 순위를 설명 유무로 바꾸지 않았고, 전체 45,716곳 중 설명 보유율은 아직 1% 미만이다. 이 20곳의 운영시간·휴무일 같은 소개 정보는 이번 공통 조회만으로 채우지 않았으며, 설명의 사실성이나 사진 품질을 독립적으로 검증하지 않았다. 실제 사용 패턴이 확보되면 빈도가 높은 위치와 후보를 기준으로 상세 수집 우선순위를 다시 정해야 한다.

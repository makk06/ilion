# 주된 방문 활동 기반 실내외 분류 · 2026-09-14

현재 분류 버전은 설명 규칙 `description_v2`, 오프라인 AI 프롬프트
`luna_context_v3`, 추천 응답 `mvp-6`이다. 이전
[문자 앵커 중심 구현 기록](./place-classification-2026-09-14.md)은 당시의
실행 결과로 보존하며 현재 계약으로 읽지 않는다.

## 판단·안전 계약

장소명·카테고리·공개 상세 설명에서 **그 장소를 방문하는 주된 활동과 공간**을
판정한다. 한 문장에 실내/야외 단어가 같이 있다는 이유만으로 혼합으로 만들지
않는다. 본 장소의 동상·성문·외벽 스크린과 연결된 전시관은 별개의 방문 대상일 수
있다. 반대로 같은 장소의 박물관·카페·데크가 주요 방문 활동이면 혼합으로 본다.
규칙은 제한된 유형과 명확한 설명 맥락에만 적용한다. `실내 전시실에 놓인 성문
복제품`을 실제 궁궐 성문인 양 실외 판정하지 않는다. 명확하지 않으면 규칙은
유보하며, 이름 규칙 또는 근거 없음으로 처리한다.

수동 `manual` 라벨은 자동 처리로 덮어쓰지 않는다. 자동 근거에는 분류 방식,
버전, 장소명·카테고리·정규화된 설명의 SHA-256 해시, 원문 연속 인용문과
위치, 주활동·범위·판단 이유, 분류 시각을 저장한다. 입력이 바뀌면 추천 시 기존
근거를 비활성화한다. 새 규칙 배포만으로 기존 유효한 v1 설명 근거나 v2 AI
근거를 만료시키지는 않는다. 407건 배치에서는 기존 설명 근거 7건을 최신
메타데이터로 재기록했다.

`gpt-5.6-luna`는 웹 요청에서 호출하지 않고, 공개 장소명·카테고리·설명만
명시적인 오프라인 CLI에서 전송한다. Responses API의 `store:false`, 추론
`none`, 엄격한 JSON schema와 출력 상한 800토큰, 설명 2,400자·요청 15초
제한을 사용한다. 출력은 `label`, `primary_activity`, 최대 2개의
`evidence_quotes`, `scope`, `ancillary_note`, `rationale`이다. 각각의 짧은
텍스트와 원문 인용문을 로컬에서 재검증하며, 설명 속 지시문은 신뢰하지 않는다.
원문에 없는 인용·명시적 부정·다른 시설만의 근거·모순된 label/scope는 적용하지
않는다. 그러나 인용문 일치는 의미의 사실 검증이 아니다. AI는 순위 영향량
0.5의 **추정**이며 `required_indoor_outdoor=indoor`의 확정 근거가 될 수 없다.
설명 규칙도 초기 정책상 0.75이지 측정된 정확도가 아니다. 혼합은 실내 필수
조건을 통과하지 않는다. 날씨 근거 필수와 실내 필수 조건은 서로 다른 필터다.

AI의 안전한 제안 필드·검증 거절 사유·토큰 사용량·입력 해시는 Attempt에
보관한다. 원본 제공자 응답·키·오류 본문은 저장하지 않는다. 같은
장소/입력/프롬프트 버전은 자동 재호출하지 않으며, 네트워크 중 DB 트랜잭션을
유지하지 않는다. 일일 상한 20회와 명령당 호출 상한을 모두 적용한다.

## 고정 20+20 평가

검수자가 실제 상세 설명 40건을 먼저 선정했다. 개발 20건은 기대값을
구현자에게 공개하고, holdout 20건의 기대값은 규칙·프롬프트 동결 및 예측
출력 이후에 공개했다. holdout 출력을 보고 규칙이나 프롬프트를 수정하지
않았다. 개발 20건의 ID·기대값과 holdout ID 목록은 읽기 전용 명령
`evaluate_place_classification`에 고정했다. holdout 기대값은 코드에 넣지
않았다. 이 40건은 편의 표본이며 서비스 전체 정확도 추정치가 아니다.

| 시점 | 개발 20 | holdout 20 |
| --- | --- | --- |
| 변경 전 | 근거 있는 라벨 13, 기대값 일치 11 | 근거 있는 라벨 3, 기대값 일치 3 |
| 규칙 동결 직후 | 규칙 결정 16, 결정한 16건 모두 개발 기대값 일치 | 신규 규칙 1 + 기존 이름 규칙 3, 모두 검수 기대값 일치; 나머지 16 유보 |
| 승인된 AI 적용 직후, 사람 검수 전 | 20건 모두 개발 기대값 일치: 규칙 16 + AI 4 | 14건 라벨, 허용 경계사례 883을 포함해 13건 일치·824 한 건 불일치·6건 유보 |
| 824 운영 회수 후 | 개발 결과 변동 없음 | 13건 라벨, 허용 경계사례 883 포함 13건 일치·7건 유보 |

엄격하게 애매한 883을 분모에서 빼면, **회수 전** holdout 19건 중
12건 일치·1건 불일치·6건 유보였다. 회수 후에는 12건 일치·7건 유보이다.
회수는 원평가의 오류를 지우는 조치가 아니라 운영상 잘못된 자동 라벨이
추천에 반영되지 않도록 한 조치다. 미호출 5건은 사전 선정한 11건 밖에 있었고,
19457은 실제 모델 제안의 원문 인용이 정확히 일치하지 않아 검증 단계에서
유보했다. 883은 펜션·글램핑이 함께 있는 경계사례여서 outdoor/mixed를
모두 허용한 검수 기준으로 따로 표시한다.

824 누리마루 APEC하우스의 모델은 실내 회의장·기념관을 주활동으로 보고
`indoor`를 제안했다. 검수 기대값은 테라스 전망을 포함하는 `mixed`였다.
이는 **holdout 불일치**로 원평가에 남긴다. 운영 라벨만 `unknown`으로
돌리고 활성 Evidence를 제거했다. Attempt의 안전한 제안·인용문·사용량과
`review_after_audit/holdout_mixed_omitted` 사유는 보존해 재호출이나
사후 성공 처리 없이 추적할 수 있다.

## 실제 적용·호출 예산

설명 보유 407건의 비용 없는 dry-run은 규칙 결정 17, 규칙상 유보 390이었다.
`would_change=14` 중 4건은 이전 개발 시드의 이름 규칙 출처 표기 변화라
적용에서 제외했다. 승인된 17건만 반영해 라벨/출처 10건이 바뀌고 기존
설명 근거 7건은 v2 해시·메타데이터로 갱신됐다. 유보 390건을 전부
미분류라고 해석하면 안 된다. 일부는 이름 추정 또는 별도 AI 근거가 있다.

이번 턴의 Luna v3 호출은 개발 미결정 4건과 holdout 사전 선정 11건,
**정확히 15회**다. 입력 8,547토큰·출력 2,608토큰이 반환 사용량으로 기록됐다.
모델 응답 직후 14건을 수락하고 19457 한 건을 유보했으며, 824는 위
사람 검수에서 운영 수락을 회수했다. 기존 v2 호출 5회를 포함한 로컬 일일
예산은 20/20으로 소진했다. 이는 비용을 보장하는 숫자가 아니라 로컬
예약/응답 사용량이다. 추가 AI 실호출은 하지 않았다.

개발 핵심 사례: 광화문(3997)과 세종대왕 동상(28656)은 연결된 지하 전시관과
분리해 `outdoor`; 제주커피박물관 바움(2687)은 본 장소의 박물관·카페·데크를
합쳐 `mixed`; 서울도서관(29634)은 다른 광장 야외 프로그램과 분리해
`indoor`다. 마지막 두 건은 AI의 낮은 비중 추정이지 실내 필수 근거가 아니다.
가상 날씨 테스트에서는 광화문·동상이 맑음의 상위 후보가 되며 비/강풍에는
실내 후보가 앞섰다. 이것은 **동일 장소·위치의 가상 예보 실험**이지 현재
실제 예보의 검증이 아니다.

재현 명령은 모두 기존 SQLite를 읽기만 하고 API를 호출하지 않는다.

```bash
cd tourist_congestion_backend
.venv/bin/python manage.py evaluate_place_classification --cohort dev
.venv/bin/python manage.py evaluate_place_classification --cohort holdout
.venv/bin/python manage.py classify_place_descriptions --limit 500
```

새 분류를 적용하거나 Luna를 호출하려면 검수한 장소 ID만 지정해야 한다.
`--apply --ai --allow-live-ai --max-calls N`을 모두 명시해야 실호출이 가능하다.
현재 일일 예산은 소진됐으므로 같은 날 추가 호출은 차단된다. 공개 추천 API와
DEBUG 전용 `/test/backend/` 시나리오는 AI 호출·DB 수집을 하지 않는다.
테스트베드의 접힌 설명 분류 사례에는 광화문·세종대왕 동상을 고정 노출하고
이전→현재 라벨, 원문 인용과 판단 이유를 표시한다. 테스트베드 서버는 로컬
개발 프로세스이며 상주 서비스·외부 배포가 아니다.

# 추천 모델 mvp-4 품질 검증 (2026-09-13)

이 평가는 기존 로컬 SQLite의 공개 장소·예보·혼잡 자료를 읽기 전용으로 사용했다. 외부 API 호출, 사용자 위치 기록, 배포는 하지 않았다. 재현 기준은 `recommendations/tests.py`의 고정 fixture와 `evaluate_pilot --at`이다. 로컬 단일 프로세스 측정은 운영 응답 지연이나 사용자 만족도를 뜻하지 않는다.

## 같은 시각의 일곱 도시 비교

2026-09-12 06:00 UTC는 로컬 기상청 예보 발표본(05:00 UTC)의 첫 대상 시각이다. 기존 05:00 UTC 재현은 이 발표본의 예보 대상이 없어 날씨 점수 0/70이었으므로 서로 비교하지 않았다. 아래의 순수 거리 기준은 같은 06:00 UTC, 같은 10km 반경·행사 유효기간·개방 필터에서 가까운 10곳을 골랐다. `mvp-4`는 같은 장소 DB와 시각에서 기본 카테고리·날씨 점수를 적용했다.

합계 날씨 점수 근거는 **31/70곳**이다. 7개 도시 모두 같은 시각의 `weather_aware=false` 결과와 기본 결과의 순위가 달랐다. 두 결과의 상위 10 중 겹치는 수는 서울 6, 부산 9, 제주 9, 대전 7, 대구 8, 광주 8, 강릉 7곳이었다. 날씨를 켰을 때 같은 기본 관광 점수의 날씨 끈 결과와 비교한 평균거리 증가는 도시별 0.036~0.201km였고, 최대 거리는 서울 0.652km, 부산 0.992km, 제주 0.947km, 대전 1.393km, 대구 0.977km, 광주 1.567km, 강릉 1.728km였다. 위의 순수 거리 기준과 날씨 끈 결과는 다르다. 후자에도 기본 관광 점수가 들어 있다.

장소 이름의 목적 적합성은 개선됐지만 정답 판정은 아니다. 순수 거리 기준 제주시 상위 3곳은 ABC마트·다이소·믹스존이었고, mvp-4는 신산공원·제주 삼성혈·민속자연사박물관이었다. 강릉은 LG전자베스트샵·롯데하이마트·커피상점에서 강릉시립미술관·강릉문화원·남산공원으로 바뀌었다. 반면 서울의 카테고리 수는 4에서 2로 줄었다. 다양성을 강제로 높이는 재정렬은 넣지 않았고, 다양성 개선이라고 주장할 수 없다. `대한노인회 강릉시지회`처럼 관광지로 등록됐어도 여행 추천에 어울리는지 의심스러운 원천 카테고리가 남는다. 카테고리 사전 점수만으로 원천 분류 오류를 해결할 수 없다.

반경 100km를 사용한 같은 시각의 추가 조회에서는 서울 기본 추천 상위 10 최대 거리가 0.652km, 제주 0.834km였다. 고정 fixture에서는 약 10km의 야외 장소와 약 80km의 실내 장소에 같은 비 예보를 주어도 가까운 장소가 앞섰다. 반경은 후보 필터이며 거리 점수는 반경에 따라 희석되지 않는다. 5km 초과 거리 보정이 먼 후보의 날씨 점수만으로 선두가 되는 현상을 제한한다. 이 사례만으로 모든 지리·선호 조합의 거리 만족도를 입증한 것은 아니다.

## 고정 시나리오에서 확인한 행동

- 부산의 동일 격자에 가까운 야외와 약 0.64km 떨어진 실내를 두면, 강수·기온·풍속이 모두 평온한 예보에서는 야외가 1위다. 장소·거리 조건을 유지하고 예보만 비로 바꾸면 실내가 1위가 되며 추가 직선거리는 약 0.64km다.
- 예보의 기온만 있고 강수·풍속이 없으면 좋은 야외 날씨로 판단하지 않고 날씨 점수를 제외한다. 일부 항목에서 비가 확인되면 그 위험만 반영하고 `partial_hazard`를 표시한다.
- `weather_aware=false`는 날씨를 순위에 쓰지 않는다. 동시에 `weather_evidence_required=true`이면 날씨·실내외 근거가 있는 장소만 남긴다. 두 값이 모두 false일 때만 날씨 보충 수집 요청을 끈다.
- 실내외 수동 라벨과 장소명 규칙 추론은 구분한다. 이름 추론의 점수 효과는 절반이며, 출처가 없는 분류는 날씨·실내외 필수 조건의 근거가 아니다. 후보 501곳이 미분류여도 뒤의 분류된 장소 격자를 보충 대상으로 찾는다.
- 결측 날씨·혼잡은 원점수 `null`이며 순위 근거에 나타나지 않는다. 순위 계산의 중립 50은 관측값이 아니다. 미확인이 확인된 악조건보다 앞설 수 있지만, 이유에서 날씨가 좋거나 한산하다고 말하지 않는다.
- 30~45분 지연 혼잡은 순위 효과를 절반으로 줄이고 한산함 필수 조건의 근거가 아니다. 기본 혼잡 선호 `any`에서 여유·보통 관측은 보너스를 만들지 않으며, 실제 혼잡 위험만 약하게 감점한다. 미래 방문에는 해당 시각의 유효한 예보는 쓰지만 현재 혼잡 관측은 연결하지 않는다. 미래 대상 시각의 예보도 발표가 5시간 넘게 오래됐으면 제외한다.
- 명시한 쇼핑 선호나 저장된 선호는 기본 관광 점수를 대체한다. 반경·실내외·한산함 필수 조건은 자동으로 완화하지 않는다. 동점 정렬은 결정적이다.

## 후속 검수와 남은 한계

### 테스트베드 검수에서 찾은 장소 분류 예외와 추가 혼잡 갱신

2026-09-13 06:17 UTC의 클릭 검수에서 `K-컬처 스크린(대한민국역사박물관)`이 장소명 속 `박물관` 때문에 실내로 추론된 오류를 발견했다. 저장된 TourAPI 소개는 전시 화면이 **대한민국역사박물관 외벽**에 있고 광화문광장 인근에서 관람한다고 명시한다. 해당 정확한 장소명 1건에만 우선하는 실외 `reviewed_name_rule_v4`를 추가해 로컬 DB 장소 ID 45367의 분류·출처·근거만 교정했다. 다른 `K-컬처 스크린(...)` 이름은 소개 확인 없이 실내나 실외로 단정하지 않도록 미확인으로 남긴다. v4도 독립 현장 정답이 아닌 검토된 이름 규칙으로, 날씨 점수 영향은 기존 이름 규칙과 같이 절반이다. 이를 전체 박물관·스크린으로 일반화하지 않았다.

같은 시각에 이미 연결된 서울 12개 영역만 유한 워커 `--max-jobs 12`로 추가 갱신했다(작업 791~802, 12/12 성공, 실패·재시도 0, 새 호출 12회, 대기 0). 공급자가 반환한 관측 시각은 05:45 UTC로 실행 당시 약 33분 지연이었고, 13개 연결 장소의 수준은 혼잡 7·보통 2·매우 혼잡 4였다. 이는 45분 사용 상한 안에서 낮은 비중의 지연 관측으로만 쓰이며, 30분 이내 근거가 필요한 `quiet_required`를 통과시키지 않는다. 서울 정기 호출 기록은 254→266회가 됐다. 날씨는 앞선 05:00 UTC 발표본이 여전히 5시간 이내라 중복 갱신하지 않았다. DEBUG 전용 [클릭 테스트베드](../README.md)는 저장 DB를 읽기만 하고 가상 날씨는 요청 안의 메모리 예보를 사용한다.

수집 전 시각(평가 실행 2026-09-13 05:37 UTC)에는 저장된 마지막 기상청 발표본이 2026-09-12 05:00 UTC로 약 하루 전이었다. 일곱 도시 상위 70곳의 날씨 점수 근거는 **0/70**이고 날씨 근거 필수 결과도 모두 0개였다. 이 결과는 만료 fallback이 정직하게 작동한다는 증거이며, 날씨 기반 추천이 지속 운영 중이라는 증거는 아니다. 최신 혼잡 관측도 만료돼 상위 70곳의 혼잡 근거는 0개였다. 이후 한 번의 제한 갱신 결과는 위 절에 별도로 기록했다.

전국 장소 45,716곳 중 실내외 분류는 4,978곳이며 모두 `reviewed_name_rule_*` 출처다. 이 규칙은 장소명 표본 검토를 거쳤지만 개별 현장 정답과 대조한 정확도 측정은 아니다. 서울 혼잡 영역과 연결된 관광 장소는 13곳이다. 날씨·혼잡 정보와 장소 품질이 충분히 넓어지기 전에는 전국 모든 지역에서 같은 추천 근거를 제공한다고 말할 수 없다. 다음 검증은 분류 규칙별 독립 정답 표본, 원천 카테고리 오류, 날씨 수집 지속성, 서울 연결 장소 확대, 실제 이용자의 선택 만족도로 해야 한다.

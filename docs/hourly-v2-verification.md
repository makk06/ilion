- 실제 D: 프로젝트에서 Flutter analyze: No issues found.

- 기존 로컬 DB를 별도 백업하고 0009 마이그레이션 적용 완료. 기존 실험 기록은 보존.

검증한 주요 동작은 시간당 평균·현재 차이 보정·음수 방지·밀도/인구 분리·시각 경계·중복과 수정 이력·늦은 수신 제외·입력 해시 재현·정답 독립성·일일 호출 상한·전역 lease·데이터 부족 승격 거부·3일 연속 악화 시 원상 복귀다.

## SQLite 보관량 부하 테스트

최종 소스의 `scripts/benchmark_hourly.py`로 새 SQLite DB를 생성했다. 부하 자료는 실제 관측과 분리한 합성 자료다.

| 항목 | 측정 |
|---|---:|
| 대상 | 20곳 |
| 관측 | 192,000건 |
| 공유 입력/발행 | 144,020건 |
| 예측 | 432,060건 |
| DB 파일 | 1,192,656,896바이트, 약 1.11GiB |
| 20곳 정시 예측 | 0.863초 |
| 20곳 최신 결과 조회 p95 | 4.35ms |
| 관측된 잠금 오류 | 0건 |

초기 기준인 정시 계산 60초 이내·조회 p95 200ms 이내를 통과했다. 원본 gzip 파일 용량과 대규모 날씨/행사 이력은 이 DB 용량에 포함되지 않는다. 단일 SQLite writer와 순차 조회를 측정했으며 다중 서버·다중 프로세스 동시 부하를 검증한 것은 아니다.

## 실제 운영 준비 상태

- 서울시: 키와 일 1,000회 한도 설정 있음. 한도상 최대 10곳이지만 현재 검증된 관광지 연결은 경복궁(POI008)·북촌(가회)한옥마을(POI060) 2곳이므로 2곳만 등록했다.
- TMAP: `TMAP_APP_KEY`, `TMAP_DAILY_LIMIT` 미설정. 실데이터 API 검증과 지원 POI 등록은 설정 대기다. 다른 출처나 데모 값으로 대신하지 않았다.
- 관련 Windows 정기 수집 예약 작업은 확인되지 않았다. 기존 수집 명령에 v2는 연결됐지만 매분 실행할 운영 스케줄러 연결은 아직 필요하다. 수집 점검의 7일 시계는 초기화가 아니라 첫 실제 수집 시도부터 시작한다.
- 현재 새 실험의 실제 관측·발행 예측은 없으며 서울시/TMAP 평가 보고서는 모두 자료 부족을 반환했다. 검증된 모델 파라미터나 앱 승격 대상은 없다.

필요한 운영 설정과 반복 실행 명령은 [hourly-crowd-v2.md](hourly-crowd-v2.md)에 정리했다. 향후 실제 인구·밀도 자료의 예측 오차와 이 코드/부하 검증 결과는 별도로 보고해야 한다.

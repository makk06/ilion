# Feedback API 명세 (초안 — 팀 논의 필요)

> 상태: **확정.** 코드 작성 착수 가능.
> 담당: 백엔드(사용자 영역) — Peak
> 관련 브랜치: `feature/be-user-feedback`

## 배경

DB 구조도의 "1. 사용자 영역" 중 `Feedback` 테이블 구현을 위한 API입니다.
이번 범위는 **피드백 저장/조회까지**이며, 신고된 값을 `CrowdData`(혼잡도 집계 테이블)에
반영하는 로직은 포함하지 않습니다. `CrowdData` 모델이 아직 없고(역할 2 담당 영역),
집계 방식은 별도의 알고리즘 설계가 필요하기 때문입니다.

## 데이터 모델 (제안)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `id` | PK | |
| `user_id` | FK → User | 작성자 |
| `place_id` | FK → Place | 대상 장소 |
| `feedback_type` | choice | ✅ **확정**: `crowd`(혼잡도 제보) / `recommendation`(추천 만족도) / `place`(장소 자체 평가) |
| `value` | 정수, nullable (0~100) | ✅ **확정**: 원본 값을 0~100으로 저장 (아래 2번 참고) |
| `memo` | 텍스트, nullable | 자유 입력 |
| `created_at` | datetime | |

✅ **확정**: 같은 사용자 + 같은 장소 + 같은 타입 조합은 **하루 1회**만 등록 가능합니다.
(기간 기준은 추후 3일/일주일 등으로 조정될 수 있음)

## 엔드포인트 (제안)

### `POST /api/feedback`

피드백 생성.

**요청**
```json
{
  "place_id": 12,
  "feedback_type": "crowd",
  "value": 72,
  "memo": "생각보다 붐볐어요"
}
```

**응답 (201)**
```json
{
  "success": true,
  "data": {
    "id": 1,
    "place_id": 12,
    "feedback_type": "crowd",
    "value": 72,
    "memo": "생각보다 붐볐어요",
    "created_at": "2026-08-09T12:00:00+09:00"
  },
  "message": "피드백이 등록되었습니다."
}
```

**에러**
- `401`: 로그인 필요
- `400`: `place_id`가 존재하지 않거나, `feedback_type`이 유효하지 않거나, `value`가 0~100 범위를 벗어남
- `429`: 같은 장소 + 같은 타입으로 오늘 이미 피드백을 남김 (하루 1회 제한)

### `GET /api/feedback`

로그인한 사용자 본인이 남긴 피드백 목록 조회 (최신순).

**응답 (200)**
```json
{
  "success": true,
  "data": {
    "feedbacks": [
      {
        "id": 1,
        "place_id": 12,
        "feedback_type": "crowd",
        "value": 72,
        "memo": "생각보다 붐볐어요",
        "created_at": "2026-08-09T12:00:00+09:00"
      }
    ]
  },
  "message": ""
}
```

## 확정된 사항

### `value` 필드의 스케일 — ✅ 확정: 0~100 정수

- 저장 시점에는 원본 값을 그대로 0~100으로 저장한다.
- 1~5단계, LOW/MEDIUM/HIGH 같은 분류가 필요하면 **조회/표시하는 시점**에 0~100 값을 가공해서 보여준다.
  (저장 시점에 미리 뭉개서 저장하지 않음 → 나중에 다른 분류 기준이 필요해져도 원본 데이터가 남아있어 재가공 가능)
- `CrowdData.crowd_score`와 스케일이 동일해서, 나중에 집계 로직을 설계할 때 별도 변환 없이 바로 비교/활용 가능.

### 이번 개발 범위 — ✅ 확정: 생성/조회 API까지

- `POST /api/feedback`, `GET /api/feedback`만 이번 범위.
- 신고 값을 `CrowdData`에 반영(집계)하는 로직은 포함하지 않음. `CrowdData` 모델이 아직 없고,
  집계 방식은 별도의 알고리즘 설계가 필요한 영역이라 역할 2(공공데이터/혼잡도) 담당 범위로 넘김.

### `feedback_type` 세 가지 값의 의미 — ✅ 확정

| 값 | 의미 | `value`의 뜻 |
| --- | --- | --- |
| `crowd` | 혼잡도 제보 | 체감 혼잡도 0~100 (높을수록 붐빔) |
| `recommendation` | 추천 결과에 대한 만족도 | 만족도 0~100 |
| `place` | 장소 자체에 대한 평가 | 평가 점수 0~100 |

세 타입 모두 `value`는 0~100 스케일로 통일한다. `memo`로 자유 의견을 함께 남길 수 있다.

### 중복 제출 제한 — ✅ 확정: 하루 1회

- 같은 사용자 + 같은 장소 + 같은 타입 조합은 **하루 1회**만 등록 가능.
- 타입이 다르면 같은 장소에도 각각 하루 1회씩 등록 가능 (예: 혼잡도 제보 1회 + 장소 평가 1회).
- 제한 기간은 추후 3일/일주일 등으로 조정될 수 있으므로, 코드에서 기간 값을 쉽게 바꿀 수 있는 형태로 구현한다.

## 향후 범위 (이번 작업 아님)

### `CrowdData` 반영 로직

- `CrowdData` 모델 설계 시점에 별도로 논의. 역할 2(공공데이터/혼잡도) 담당 범위.

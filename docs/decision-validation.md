# 방문 판단 검증 계약

2026-09-15 · `relative-choice-v2`. 인구 예측 공식 `hourly-mean-v2`와 수집 주기는 변경하지 않는다. 30일 모델은 별도 실험으로 유지하며 자동 승격하지 않는다.

## 평가와 승격

`places/services/hourly_decisions.py`가 발행 전에 확보된 84일 분포로 예측과 정답의 백분위를 계산한다. 중간 순위로 동률을 처리하며 단계 경계는 20·40·65·85다. 0은 유효값이다. 정답을 새로 연결해도 발행 당시 분포를 다시 미래 자료로 만들지 않는다.

장소·거리마다 한산 안내(≤40) 중 실제 붐빔(>65) 비율 ≤5%, 평소보다 매우 붐빔(실제 >85, 예측 ≤85)의 놓침률 ≤10%를 요구한다. 각각 최소 50·20건, 14일이 필요하다. 분모, Wilson 95% 구간, 한국 정답 날짜 단위 2,000회 재표집한 단순 평균 대비 차이 구간을 보고한다. 점추정이 악화되면 FAIL, 비악화를 판단할 근거가 부족하면 NEEDS_MORE_DATA다. 숫자 오차 평가의 최고 혼잡 사례도 실제 백분위 >85로 선택한다. 고정된 학습 인구 임계값은 새 시간당 모델의 판단·승격에 사용하지 않는다. 기존 평균 오차와 제공률 조건은 유지한다.

상대 점수는 `100 × (과거 값 중 예측보다 작은 개수 + 0.5 × 같은 개수) / 과거 값 개수`다. 과거 분포는 같은 공급자·대상·지표의 발행 당시 확보한 자료로 고정한다. 실제값도 동일 분포로 변환한다. 85는 '붐빔'이고 85 초과가 '매우 붐빔'이다. 장소 수용률이나 다른 장소보다 절대적으로 사람이 적다는 의미가 아니다. 단위의 크기만 달라져도 결과가 달라지는 인구수 기준을 대체한다.

순위는 공급자·지표·관측 범위·발행·대상 시각이 같은 고유 대상끼리 비교한다. 실제 동률을 제외하고, 어느 모델이든 예측 동률이면 방향 비교 공통 쌍에서 제외하여 별도 집계한다. 최소 2개 대상·100쌍·14일이 필요하다. 예측·실제 모두 동률인 건수도 기록한다. 순위 검증은 단계 안내와 독립적으로 보고하며 단계 안내가 실패한 모델을 앱에 노출하지 않는다.

16개 후보 중 사용성 통과 후보를 우선한다. 순위까지 통과한 후보가 있으면 그 집합에서 NMAE가 가장 낮은 구성을 선택한다. 통과 후보가 없으면 NMAE 최저 구성을 실험용으로만 남긴다. 계약의 경계·허용치·코드 버전·선택 통과 여부를 기존 선택 해시에 포함한다. 과거 PASS 또는 변경된 계약은 사용할 수 없으며 새로운 미관측 최종 평가 및 실제 발행 평가가 필요하다.

최근 7일의 충분한 표본에서 3일 연속 숫자 오차 또는 단계 판단이 악화되면 대상 승격을 해제한다. 순위만 3일 연속 악화되면 순위 기능을 중지한다. 표본 부족을 통과로 간주하지 않는다.

## API와 화면

기존 응답에 `relative_label`, `decision_contract_version`, `guidance_eligible`, `ranking_eligible`, `decision_reasons`를 추가한다. `normalization=within_target_empirical_percentile`과 공급자·지표·단위·scope를 함께 전달한다. TMAP 밀도는 인구 필드에 넣지 않는다.

Flutter `CrowdForecast`가 신원·단위·검증 계약·정시 시각·1~3시간 범위를 검사한다. 방문 선택은 지금 또는 제공된 절대 정시만 가능하다. 화면은 한국 시각을 표시하며 만료된 선택은 사용자에게 재선택을 요청한다. 현재값이나 인접 시간으로 대체하지 않는다.

추천 카드·이유·정렬은 동일 방문 시각의 입력을 사용한다. 미래 혼잡 점수는 순위 검증까지 통과해야 추천 적합도에 반영한다. 단계만 검증된 경우 단계 표시는 가능하지만 혼잡 순위에는 넣지 않는다. 순위 정렬은 같은 공급자·지표·범위·발행 그룹 안에서만 제공한다. 그룹 사이 순서를 절대 밀집도 비교로 설명하지 않는다. 근거가 없으면 혼잡 항목을 제외하고 다른 선호 조건으로 추천한다.

## 반복 실행

저장소 루트에서 보조 재현: `.integration-venv/Scripts/python.exe scripts/validate_hourly_proxy.py --help`로 입력·출력 옵션을 확인한다. 기존 생활인구 자료는 운영 DB에 넣지 않고 별도 산출물 폴더를 사용한다.

백엔드 폴더에서 `python manage.py hourly_crowd select --provider seoul`, `evaluate --provider seoul --artifacts <폴더>`, `shadow --provider seoul --artifacts <폴더>` 순으로 실행한다. TMAP은 공급자 인자를 바꿔 독립 실행한다. 기간이 부족하면 NEEDS_MORE_DATA로 반환한다. 주기 작업의 `advance`도 동일 계약을 적용하며 자동 승격하지 않는다.

검증: 백엔드 `python manage.py test --noinput`; 프런트엔드 `flutter analyze --no-pub`, `flutter test --no-pub`, `flutter build web --no-pub`. 화면 회귀 테스트는 선택·공급자 그룹·결측·만료 상태를 검사한다. 합성 테스트 통과와 실제 성능 통과는 별개다.
